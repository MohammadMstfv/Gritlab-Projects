# Ethical AI

## What I learned

This exercise taught me that AI is more useful as a learning assistant than as a replacement for learning. I can ask AI to explain code, generate examples, create buggy versions, and point out possible edge cases, but I still need to understand what the code is doing and be able to fix problems myself. Getting a correct answer immediately can actually make learning weaker if I don't investigate why the answer is correct.

## My most important insight

My most important insight came from **Exercise 01**, where I worked with a sorting function for a linked list. A small change such as using `<` instead of `>` can make a program produce the opposite result while still running without any error. This showed me that "the code runs" does not mean "the code is correct." Asking AI to deliberately introduce a bug and then analyzing the difference helped me understand that debugging is not just about finding syntax errors; it is about checking whether the program actually behaves according to its intended purpose.

## How I will use this workflow

I will use the same workflow throughout the rest of the curriculum: first attempt the problem myself, then use AI to explain concepts or challenge my solution rather than simply asking for the final answer. When I use AI-generated code, I will read it line by line, test it with edge cases, and try to explain why it works. I can also ask AI to create bugs, alternative implementations, and questions that test my understanding. The goal is to use AI as a second pair of eyes and a learning partner while keeping the actual understanding and problem-solving ability mine.
